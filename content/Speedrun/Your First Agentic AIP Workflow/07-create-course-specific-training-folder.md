# 07 — Create a Course-Specific Training Folder

*Module: Setting Up Your Project & Folder · Inspected September 12, 2026 · Notes: Ready for Review · Practice: Not Started*

## Give this experiment one identifiable home

Inside the learning Project, the lesson suggests favoriting the Project and creating a folder through New → Folder. Name it after the current course, for example `Speedrun: Your First Agentic AIP Workflow`. Favoriting makes navigation easier; it does not install the course or change the underlying resources.

The folder becomes the destination for the Marketplace installation and the Logic function you create later. Keeping those artifacts together makes it easier to inspect a complete exercise without confusing it with the previous AIP workflow.

Your local notes follow the same organizational intent under `Learn/Speedrun/Your First Agentic AIP Workflow`, with one file for each inspected lesson. The local files do not represent an installed Foundry course folder.

## Why a separate folder helps debugging

Imagine opening a function named Review Patient for Clinical Trial several weeks from now. If its folder contains the matching installation and Workshop module, you have a useful starting point for finding its object types and dependencies. If copies are scattered across several places, you first have to discover which version and data belong together.

Folder organization therefore lowers investigation cost. It does not prove the function references the resources in that folder. References can still be configured incorrectly, so later input and Action checks remain necessary. Keep the distinction between visual organization and actual dependency binding clear.

## A sensible resource record

During later practice, record the learning Project, course-folder location, Marketplace installation and username suffix. Once created, add the Logic resource and selected object types. This is a short map for reproducibility, not another progress tracker. The central progress file remains the single authority for learning status.

Use one folder unless you have a clear reason for another experiment. If you intentionally compare variants later, name the variants by what changes and keep their baseline identifiable. Do not create anonymous “copy,” “new” and “final” variants that make evaluation results impossible to associate with a configuration.

The source notes that folders and files can be renamed from their context menu. Renaming for clarity is different from proving that all external references and resource identities changed; inspect the actual resource when such a distinction matters.

**Remember:** choose the installation destination before installing. It is much easier to keep a coherent exercise from the start than to reconstruct which assets belong together afterward.

**Review question:** does a course folder named with your username guarantee the selected Patient type is yours? No. The later type selector must point to the correctly prefixed type from your installation. Naming helps you find it; explicit binding determines what the function uses.
