*Module: Setting Up Your Project & Folder · Inspected September 12, 2026 · Notes: Ready for Review · Practice: Not Started*

## A place for the whole learning workflow

The course recommends one learning Project for your training material and a dedicated folder for each course. Replace the `<username>` placeholder with your actual login identifier wherever the instructions use it. An organization's own Project convention may take precedence in its enrollment.

A Project is the container in which the course expects its resources to live. A folder organizes those resources within the Project. The distinction matters because a collection of neatly named resources is not enough if they were created in a location unsuitable for the tools that need them.

On your computer, the equivalent notes live in `Learn/Speedrun/Your First Agentic AIP Workflow`. That local folder is documentation, not a Foundry Project. Creating these Markdown files does not create any Foundry resource or synchronize anything into your enrollment.

## Why organization is a technical concern

Suppose two learners install the same Marketplace package. Both now have something displayed as Patient and an application with a similar name. If your function binds to the other learner's type, the UI may still look reasonable, but your test data and edit target are wrong. Naming and resource-location discipline reduce the chance of that mistake; later lessons still require checking the actual selected types and objects.

For a software engineer, think of the learning Project as a workspace with dependencies and access, and course folders as an organizational convention inside it. The comparison is useful, but a directory name is not a guarantee of security or isolation. Verify those properties in the platform rather than deriving them from naming alone.

The lesson also mentions different Project structures for production workflows. Do not transplant the single-learning-Project convention into every production design. Shared ownership, data sensitivity, lifecycle and deployment boundaries may justify a different arrangement. The tutorial's goal is to give one learner a navigable place to work.

## Before creating anything later

Find out whether you already have a usable learning Project. Reuse it if appropriate; otherwise identify the permitted Project-creation route or administrator-provided location. Decide on one course folder name and record it. Avoid creating another Project merely because a screenshot begins with New project.

This modest discipline pays off when you reach evaluation and automation: you need to know which function and object types belong to the same exercise, and where their supporting resources were installed.

**Check:** can you explain the difference between your local Learn folder, the Foundry learning Project and the course-specific Foundry folder? If they sound interchangeable, pause here. They serve related organizational purposes but exist in different systems and do not imply the same runtime capabilities.
