# 06 — Create a Foundry Learning Project

*Module: Setting Up Your Project & Folder · Inspected September 12, 2026 · Notes: Ready for Review · Practice: Not Started*

The official lesson allows you to skip Project creation if your learning Project already exists. That is the first decision in this exercise, not an optional optimization after creating another copy.

## The intended setup path

When creation is needed and permitted, open Files in Foundry's left sidebar, choose New project, and give it a name such as `Learning (<username>)`. Add a description explaining that it contains personal training resources. Select the organization's namespace if that selector appears. The lesson specifies a default role of Discover, then Create.

If creation is unavailable, use an appropriate existing Project or have one provided through the administrator path described in the permissions lesson. The source explicitly warns against using Your files or the home folder because some required tools cannot be accessed there.

These are instructions for the later practice phase. No Project was created while preparing these notes.

## Why each choice matters

The name helps you find the right environment. The description helps another person distinguish a learning workspace from a production application. The namespace selects an organizational context when the enrollment exposes that choice. The role setting concerns access; it is not simply a cosmetic default.

Do not assume that selecting Discover proves your training data is private or that all necessary permissions are now present. The installed enrollment and its policies determine effective access. Use the course's training instructions together with local policy and verify the permissions required for the actual operations.

A practical analogy is creating a service repository under the correct organization. You need more than a repository name: ownership, access and the ability to create dependent resources also matter. Here, choosing a valid Project gives subsequent Logic and installation steps a suitable destination.

## Reuse without confusion

If a Project already exists from the previous speedruns, check that it is actually yours or explicitly assigned to you. Confirm that you can use the course folder and relevant tools. Reusing the intended learning Project keeps the workspace coherent; reusing an unrelated team's Project only because it is writable creates ownership confusion.

The verification evidence later should be the Project's identity and location, whether it was reused or newly created, and the result of the capability check. A screenshot of a similarly named Project without context is weak evidence.

**Troubleshooting question:** you cannot see AIP Logic under New while inside Your files. What should you check before assuming that the model service is unavailable? First check the resource location against the course's Project requirement, then distinguish a missing authoring permission from a model-access issue. These failures occur at different stages.
