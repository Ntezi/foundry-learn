# 04 — Introduction — Project Setup

## A Project is the home of the workflow

The course recommends one Learning Project for your training work, with a separate folder for each course. You already have other Foundry studies, so the practical starting point is to locate and reuse the appropriate Learning Project rather than create another by default.

A Project is more than a visual directory: it is an organizational and access boundary for resources. A course folder makes the training resources easier to navigate inside that boundary. Do not assume a folder alone establishes a completely independent security policy.

## Why naming matters in a shared platform

The course uses `<username>` as a placeholder for your login identifier. Replace it when following names intended to distinguish your work from other learners. A display name such as Chunks can appear in several users' projects; the resource's identity and location determine which one your pipeline or Ontology uses.

This is similar to having several repositories or database schemas with tables named `users`. The name is meaningful only within the correct context. When debugging a wrong dataset, record its full location or resource identity, not just its label.

## Keep local study organization and Foundry organization distinct

These notes live locally under `Learn/Speedrun/Your First AIP Workflow`. That is the requested study-library structure. It does not create a Foundry Project, folder, dataset or application. The platform resources will be created only during later practice.

Inside Foundry, the course's one-Project convention makes a small learning exercise manageable. The lesson also points to production project-structure guidance, where separating stages can support different ownership and sharing needs. Do not interpret a convenient training layout as the only production architecture.

## The purpose of this setup work

A stable home prevents resource confusion as the workflow grows from a media set to a pipeline, three datasets, two object types, a graph and an application. It also makes it easier to return after a pause and know which resources belong together.

Before later creation, identify the existing Learning Project, confirm it is the intended training location and check whether the course folder already exists. This is ordinary duplicate avoidance, not a new approval gate.

**Remember:** organizing resources is part of making the workflow understandable and maintainable. Explain why two resources named Chunks need not contain the same data and why a local notes folder is not evidence that either exists in Foundry.
