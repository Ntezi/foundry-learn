# 05 — Create a Foundry Learning Project

The purpose of this step is to establish an appropriate place to build and revisit the training workflow. If you already have a suitable learning Project, use it. Creating another one does not add to the learning outcome.

## Walk through the choices, not just the buttons

The course's written setup flow is **Files → Projects → New Project**. Select the appropriate organization space and Project template, give the Project a recognizable name and description, and omit the optional Portfolio for this exercise.

The space/template choices establish the context in which the Project is created. They can depend on your enrollment's setup, so use the available training context rather than guessing from a different course's screenshot. A description such as “Foundry learning exercises for Marius” communicates purpose better than an unexplained test name.

In **Advanced**, the course warns that other users may default to Editor and directs you to choose Viewer to prevent their edits. The intention is controlled collaboration: people who can inspect a training resource do not automatically need to modify it. Apply this instruction to the new learning Project you are configuring. An existing shared Project may have intentional permissions that should not be overwritten to resemble the tutorial.

The current E2E lesson uses the organization space/template flow and Viewer setting. Older notes from other courses mentioned Discover; do not mix the two procedures. The course also directs learners away from the home/Your files area for this setup.

## What has actually been created?

At the end, you have a Project in which subsequent resources can be organized. You have not ingested orders, created the pipeline or defined an Order object. This separation helps when diagnosing problems: a successful Project creation only demonstrates that this particular setup operation worked.

Think of this as establishing the project context before creating application resources. It is similar in purpose to selecting the correct cloud project before provisioning infrastructure, although Foundry's permission and resource models are its own.

## Verify a useful outcome

Open the Project from the Projects list, confirm its name and location, and check that it is the intended training destination. Inspect the effective access that is relevant to your next task. The fact that another user is a Viewer is not a complete description of every permission on every resource used by a future application.

If you cannot create a Project, the permissions lesson allows an administrator to supply one. That is a legitimate setup path: learning pipeline design does not require unrestricted administrative access.

**What to retain:** choose a known training context, make ownership understandable, and distinguish viewing from editing. These habits carry over to shared development environments and internal application work.
