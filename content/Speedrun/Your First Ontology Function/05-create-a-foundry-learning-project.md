# 05 — Create or reuse the learning Project

The goal is a suitable location for the course's resources. Reuse an existing learning Project if it meets that need. If one must be created, this course's reviewed procedure uses **Files → New project**, a descriptive name, the organization namespace if shown, and **Discover** as the default role.

The course advises against using the personal home area because some required tooling is unavailable there. Select the actual learning Project rather than assuming that any location with a New button provides the same capabilities.

## Why this procedure differs from the previous course

The E2E lesson used a space/template flow and a Viewer setting. The reviewed Ontology Function lesson describes the namespace/Discover flow. These are course-specific instructions; do not combine them into one imagined procedure or change an existing shared Project merely to make it resemble another tutorial.

Interfaces and templates can differ by enrollment and version. If your screen differs, identify the corresponding training context and effective access rather than guessing from the closest-looking label.

## What Discover does not establish

Treat the stated role as this lesson's setup choice. It is not evidence that another user can read all records, create repositories or run an Action. Verify each required operation in its own context.

As a software engineer, compare selecting a Project with choosing a cloud project or organization for development. The selected context matters to resource creation, but it does not automatically satisfy every service-specific permission.

The course allows an administrator to provide the Project if creation is unavailable to the learner. That alternative preserves the educational objective: you can learn functions without being the administrator of the environment.

## Make the purpose understandable

A name such as `Learning (<username>)` and a description identifying the training purpose help colleagues distinguish this from a shared operational Project. The username is a collaboration aid, not a substitute for a stable resource identity.

After opening the Project, confirm its location and that it is the intended destination for this course's folder. If the Project already contains your E2E exercise, that does not mean its Order type is the correct model for this course. You will use the separately installed Clinic and Financial types.

## A useful setup outcome

You should be able to say which Project will contain the course resources, why it is appropriate and which creation operations are available there. At this point, no function, SDK or clinic calculation follows automatically from that choice.

**What to retain:** reuse an appropriate environment, keep the exact tutorial's setup context clear, and verify capability rather than inferring it from a familiar role name.

**Check yourself:** why shouldn't you create this Function over the previous Marius Order type? The business model and required fields are different. Reusing a Project is useful; reusing unrelated object dependencies would be a modeling error.
