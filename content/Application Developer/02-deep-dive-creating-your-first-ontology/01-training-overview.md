# Lessons 1-2 — Training Overview

## What the Ontology is

Foundry presents commonly used organizational data as **objects**: recognizable real-world things such as an aircraft, customer, order, or employee. An object can combine information from several source systems into one operational view.

The **Ontology** defines the organization's shared model of those things:

- **Object types** describe the kinds of things the organization works with.
- **Properties** describe each object.
- **Links** describe relationships between objects.
- **Actions** describe what users are allowed to do to or with objects.

This model is organization-specific. The same object type can have different properties and relationships in different organizations because their operational needs differ.

## Why it matters

The Ontology is more than a technical schema. It gives people, applications, and AI systems a shared operational vocabulary. This makes data easier to understand and reuse, connects data to real decisions, and supports governed actions in day-to-day workflows.

## Course outcome

The course uses the **Fresh Air** example to teach how to:

1. Explore an existing Ontology in Object Explorer.
2. Trace its supporting data through Data Lineage.
3. Extend it in Ontology Manager.
4. Create an object type, link type, and action type.
5. Execute the action and observe the operational result.

## Required access

The course needs access to Marketplace, Object Explorer, Data Lineage, and Ontology Manager. Completing all hands-on work also requires permission to deploy Marketplace resources and create Ontology assets. There is no workaround for missing object, link, or action creation permissions.
